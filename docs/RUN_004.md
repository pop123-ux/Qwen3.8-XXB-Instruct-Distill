# Run 004 — Computational-Behavior / Delta KD

**Status: prepared, not run.**

Run 004 is the first experiment targeting the project's central **Beyond Layer Matching**
hypothesis. Run 003 used conventional pointwise intermediate matching:

`h_student[l+1] ≈ h_teacher[m(l)+1]`

Run 004 instead matches the **residual contribution** made by each student layer to the
teacher's complete span assigned to that layer:

`h_student[l+1] - h_student[l] ≈ h_teacher[b] - h_teacher[a]`

where `[a,b)` is the teacher-layer span assigned to student layer `l`.

This distinction matters for a depth-reduced student: conventional pointwise matching leaves
16 teacher layers without direct student anchors, while the delta formulation charges every
teacher layer to exactly one student span. The teacher-span construction is validated by
`qwen_distill.distillation.behavioral.layer_spans`.

## What Run 004 tests

The experiment asks whether matching **what computation changes in the residual stream**
produces stronger teacher-behavior alignment than matching fixed intermediate layer
positions.

A positive result is not "the delta loss fell." The primary scientific comparison is whether,
at a matched training budget, Run 004 improves output-level teacher imitation and held-out
behavior relative to Run 003, including:

- teacher KL / KD divergence;
- student/teacher top-1 agreement;
- validation loss;
- and, only in later capability runs, downstream benchmark quality.

No SOTA or capability claim is attached to this preparation or to a short 128-step run.

## What is and is not matched

The following are intended to remain identical to Run 003: teacher revision, tokenizer/corpus,
student checkpoint, LoRA geometry, optimizer, sequence length, batch size, accumulation, step
count, seed, precision, KD temperature, teacher top-k, checkpoint cadence, and gradient
checkpointing.

The research variable is the **representation target**: pointwise hidden-state matching in
Run 003 versus residual-contribution matching in Run 004.

## What is not implemented

Run 004 does **not** match the internal DeltaNet recurrent-state tensor. The teacher and student
recurrent states have incompatible shapes, so introducing a learned projection would create a
new modeling choice that has not been justified or validated. The behavioral module therefore
refuses that state-level request instead of silently substituting the residual proxy.

## Memory strategy

Use the same chunked loss machinery validated for Run 003. Chunking changes when gradients are
taken, not the mathematical objective: the same spans, positions, normalisation and `1/n`
reduction are used. The chunk size is 4.

A fresh Pod should still perform the normal memory calibration before launching a longer run.
The Run 003 L40S calibration established that the chunked execution can fit under the existing
42 GiB allocation safety gate; the new Pod and final configuration should be re-measured rather
than assuming an old hardware number is exact.

## Evidence interpretation

### Evidence for the hypothesis

A stronger result would be observed if, under matched compute and student initialization,
Run 004 reaches better output-level teacher alignment and validation behavior than Run 003,
and the advantage survives longer-budget capability experiments.

### Evidence against the hypothesis

Evidence against the hypothesis would be a persistent failure of delta matching to improve
output-level teacher alignment or validation behavior relative to the matched layer-KD control,
including after controlling for the measured training objective and budget.

### Inconclusive outcome

If delta loss improves but KL, agreement, validation, and later capability do not improve, the
experiment establishes that the new objective is trainable but does not establish a useful
advantage. That is still a valid result.

## Recurrent-state follow-up

If the residual-contribution result is promising, a later experiment can investigate true
DeltaNet-state matching as a separate research question. That experiment should first define
and validate an explicit teacher-to-student state mapping/projection rather than adding it to
Run 004 implicitly.
