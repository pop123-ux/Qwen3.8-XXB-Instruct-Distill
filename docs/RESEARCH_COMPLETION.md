# Research Completion Campaign

This document defines the evidence sequence required before the project makes a capability claim. The paper is first-hand: claims about the custom student must be supported by artifacts generated by this repository, not by expectations from the architecture.

## Non-negotiable constraints

- Frozen student: `qwen38_19b_h5120_l48_moe`
- Total parameters: `13,008,505,728`
- Active parameters/token: `9,611,119,488`
- Teacher: `Qwen/Qwen3.8-27B`
- Teacher revision: `dbdc473dea0d6a9763042881cc33d6058d1742d2`
- Target inference envelope: 16 GiB end-to-end GPU resident memory
- Training operational ceiling on the L40S: **45 GiB used GPU memory**
- Canonical training protocol for the RQ1 control pair: 1536 tokens, batch 1, gradient accumulation 1, bf16, QLoRA r=16 alpha=32 dropout=0.05, AdamW, seed 0, teacher 4-bit NF4, temperature 2, teacher top-k 64, chunk pairs 4.

The 45 GiB ceiling is an operational stop condition, not a claim about deployment memory.

## RQ1 — Beyond Layer Matching

### Step A: establish the controlled comparison

Run 003 is the pointwise intermediate-KD control. The matched behavioral replication is named `run004_matched_behavioral_kd` and differs only in representation target.

**Run 003:** pointwise layer matching.

**Run 004-M:** residual contribution matching:

`student h[l+1] - h[l]` against `teacher h[b] - h[a]` for each assigned teacher span `[a,b)`.

Both runs must use the same 700,000-token corpus cap, same sequence length, same seed, same student initialization, same optimization configuration, and same L40S hardware for the final paper comparison.

The repository provides the exact matched command in `experiments/run004_matched_behavioral_kd/command.txt` and the launcher accepts `--max-tokens` specifically to prevent sampler-pool drift.

### Step B: do not stop at 128 steps

The 128-step matched run is a controlled mechanism experiment. It is not sufficient evidence for a final capability claim.

If the matched result is positive or non-inferior, continue with the same objective using staged budgets:

1. **1,024 steps** — early scaling check, 1,572,864 training tokens.
2. **4,096 steps** — serious short distillation, 6,291,456 training tokens.
3. **16,384 steps** — only if the previous trajectory remains healthy and budget permits.

Every stage must remain under the 45 GiB GPU-memory guard and inherit the same student initialization unless the experiment explicitly states otherwise.

A longer run is an escalation of evidence, not a replacement for the matched control.

## RQ1 — final model objective selection

The paper must compare at least these teacher-supervision families before selecting the final training objective:

- CE-only control.
- Pure logit KD.
- Pointwise layer/intermediate KD.
- Behavioral/delta KD.
- Composite CE + logit KD + behavioral KD.

The composite objective is not assumed to win. It is a hypothesis to test after the controlled pure-objective results are available.

For every arm, record the same core outputs:

- training loss trajectory;
- held-out language-model loss;
- teacher KL/KD divergence;
- teacher/student top-1 agreement;
- behavioral loss and its magnitude/direction components where applicable;
- peak allocated/reserved GPU memory;
- throughput;
- checkpoint identity and hashes.

## RQ2 — Context-Length Specialization

RQ2 is not considered answered by RQ1.

The context study must keep the student, teacher, optimizer family, total token budget, seed policy, evaluation suite, and deployment accounting controlled while varying the **training-context distribution**.

Required arms:

- uniform context mixture;
- short-context-heavy;
- medium-context-heavy;
- long-context-heavy;
- progressive context schedule.

Target context regimes are 4K, 8K, 16K, 32K, 64K, 128K, and 262K. The training system must explicitly record the distribution rather than only the maximum sequence length.

The primary result is a capability-vs-evaluation-context curve for each training distribution. A context curriculum is supported only if the measured curve improves in a controlled comparison without an unacceptable memory or throughput penalty.

## 16 GB deployment claim

A model is eligible for the project's final 16 GB claim only after hardware measurement or a fully specified deployment accounting demonstrates that the **complete runtime footprint** fits the 16 GiB boundary:

- weights;
- quantization overhead;
- KV cache;
- recurrent state;
- convolutional state;
- runtime/workspace overhead.

Parameter count alone is never sufficient.

## Competitive-model claim

The phrase "competitive with 16 GB SOTA" is a target until directly measured.

Before the paper makes that statement, evaluate the final candidate and relevant 16 GB competitors under a documented, reproducible evaluation suite and compare:

- capability quality;
- long-context behavior;
- peak inference memory;
- throughput / latency;
- quantization configuration;
- context length supported.

Third-party competitor values must remain marked as reported rather than measured here in the ledger.

## Paper evidence policy

The manuscript should distinguish three evidence levels:

**Measured here:** produced by this repository on recorded hardware with preserved artifacts.

**Reported elsewhere:** third-party benchmark or price data with an explicit citation.

**Estimated:** analytical values with the estimation method preserved.

A missing experiment remains missing in the paper. The repository should prefer an explicit "not yet measured" result over a filled gap.
