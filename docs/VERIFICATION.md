# Verification Status

This project's rule is: **no architectural claim enters the repository unless it is
traceable to a primary source.** This file records, for every claim we rely on, where
it came from and whether it is confirmed.

Last updated: 2026-08-22.

## Network constraint affecting verification

The session that authored this repository **could not reach `huggingface.co`** — the
host is blocked by the execution environment's egress policy (confirmed for both
direct HTTPS and the fetch tooling; the proxy reports
`gateway answered 403 to CONNECT` for `huggingface.co:443`). Several secondary
technical hosts (`recipes.vllm.ai`, `northflank.com`, `modelscope.cn`, `qwen.ai`)
are blocked as well.

Consequences, stated plainly:

- The upstream **model card, `config.json`, tokenizer, and chat template for
  `Qwen/Qwen3.8-27B` have not been read directly.**
- The **license was not read from the repository itself.**
- No teacher weights were downloaded, so no checkpoint cross-check was performed.

What we *could* do instead is verify against the **reference implementation**, which
is distributed on PyPI and was reachable. That is a strong source: it is the code
that actually runs the model, not a description of it.

**Anyone reproducing this work should run `scripts/inspect_teacher.py` against the
real checkpoint before relying on the numbers here.** The script is built precisely
to close this gap, and `cross_check()` will report a MISMATCH if our analytical model
disagrees with the checkpoint.

## Tier 1 — Verified from the reference implementation

Source: `transformers==5.15.1`, downloaded from PyPI and read directly
(`transformers/models/qwen3_5/{configuration,modeling}_qwen3_5.py`). This is the
`Qwen3_5` architecture family; see the open question below about `Qwen3.8`.

| Claim | Evidence |
|---|---|
| Hybrid layout is generated by `full_attention_interval`, default 4 | `Qwen3_5TextConfig.__post_init__` |
| Expansion rule: `"linear_attention" if bool((i+1) % interval) else "full_attention"` | same |
| Therefore every 4th layer is full attention and the **last** layer of each group is full attention | derived; pinned in `tests/test_spec.py` |
| Padded vocab size 248320 | `Qwen3_5TextConfig.vocab_size` default |
| `head_dim` 256 for full attention | `Qwen3_5TextConfig.head_dim` default |
| `partial_rotary_factor` 0.25 → RoPE dimension 64 | `__post_init__` sets the default; `head_dim * 0.25 = 64` |
| DeltaNet: `linear_key_head_dim` 128, `linear_value_head_dim` 128, `linear_num_key_heads` 16 | config defaults |
| DeltaNet conv: depthwise, `groups=conv_dim`, `bias=False`, kernel 4 | `Qwen3_5GatedDeltaNet.__init__` |
| `conv_dim = key_dim * 2 + value_dim` | same |
| DeltaNet projections are `in_proj_qkv`, `in_proj_z`, `in_proj_b`, `in_proj_a`, `out_proj` | same |
| **Gated attention: `q_proj` emits `n_heads * head_dim * 2`** — the second half is a sigmoid output gate | `Qwen3_5Attention.__init__` and `attn_output * torch.sigmoid(gate)` in `forward` |
| `q_norm`/`k_norm` are RMSNorm over `head_dim` only | `Qwen3_5Attention.__init__` |
| MLP is SwiGLU: `gate_proj`, `up_proj`, `down_proj`, no bias | `Qwen3_5MLP` |
| **Recurrent state shape is `(batch, num_v_heads, head_k_dim, head_v_dim)`** — constant in sequence length | `torch_recurrent_gated_delta_rule` |
| **The checkpoint ships `mtp.*` weights, and `transformers` discards them** | `_keys_to_ignore_on_load_unexpected = [r"^mtp.*", ...]` on `Qwen3_5PreTrainedModel` and `Qwen3_5ForCausalLM` |
| **A text-only causal LM can be loaded from the multimodal checkpoint** | `Qwen3_5ForCausalLM._keys_to_ignore_on_load_unexpected` also ignores `^model.visual.*` |
| The family is multimodal: `Qwen3_5Config` has `vision_config` + `text_config`, and `Qwen3_5ForConditionalGeneration` exists | `configuration_qwen3_5.py` |
| Upstream code is Apache-2.0 | license header in the transformers Qwen3.5 sources |

### Derived and self-consistent

Applying the parameter formulas transcribed from the above to the **publicly reported
Qwen3.8-27B configuration** (hidden 5120, 64 layers, FFN 17408, vocab 248320, 24 query
/ 4 KV heads at head_dim 256, 48 value / 16 key DeltaNet heads at dim 128) yields:

```
26,895,998,464 parameters  =  26.90B
```

This lands within 0.4% of the advertised "27B". Reproducing a published parameter
count from independently transcribed shape formulas is meaningful evidence that both
the formulas and the reported configuration are correct. It is pinned as a regression
test in `tests/test_params.py::test_teacher_spec_reproduces_published_27b`.

It is **not** proof that Qwen3.8-27B uses exactly these values — only that these
values are mutually consistent with a 27B model in this architecture family.

## Open questions — resolve before committing to an architecture

1. **Does `Qwen3.8-27B` load as `model_type: qwen3_5`, or does it need a newer
   `transformers`?** `transformers==5.15.1` (latest on PyPI as of 2026-08-22) contains
   `qwen3_5`, `qwen3_5_moe` and `qwen3_next`, but **no `qwen3_8` module**. Either the
   3.8 checkpoint reuses the `qwen3_5` classes, or it requires a release/`trust_remote_code`
   we have not seen. This determines whether our student is loadable by stock
   `transformers` at all, so it is the single most important thing to check first.
2. **Exact teacher config values.** Read `config.json` and confirm `num_attention_heads`,
   `num_key_value_heads`, `linear_num_value_heads`, `intermediate_size`, and
   `layer_types` against the values assumed in `configs/teacher/`.
3. **License and naming.** Read `LICENSE` in the upstream repo and any naming or
   attribution requirements before choosing a public model name.
4. **The `medium` no-op.** If confirmed, this is directly relevant to the project's
   reasoning-efficiency objective: it would mean the teacher's own budget control is
   partly non-functional, strengthening the case for training an explicit budget
   mechanism into the student rather than inheriting the teacher's.
5. **Whether smaller Qwen3.8 family members exist.** We found no evidence of one. If
   none exists, the "start from a smaller same-family base" initialization path is
   unavailable and teacher surgery becomes the primary option — a significant change
   to the training plan (see `docs/PROJECT_PLAN.md`).

## How to close these gaps

```bash
pip install -r requirements/base.txt
python scripts/inspect_teacher.py --repo-id Qwen/Qwen3.8-27B --config-only \
    --json evaluations/baselines/teacher_config_report.json \
    --save-spec configs/teacher/qwen3_8_27b.verified.json
```

Then, with the weights available locally:

```bash
python scripts/inspect_teacher.py --path /path/to/Qwen3.8-27B \
    --json evaluations/baselines/teacher_checkpoint_report.json
```

Commit both reports. If `cross_check` reports MISMATCH, fix
`src/qwen_distill/architecture/params.py` before trusting any estimate in this repo.
